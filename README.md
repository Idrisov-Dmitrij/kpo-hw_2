# ПОС — Преподавательская Оценка Студентов

Консольное приложение на Go: студенты, рубрикатор критериев, оценки, расчёт итога по весам и выгрузка итога в CSV/JSON.
Реализовано по DDD, в архитектуре **Ports and Adapters (Hexagonal)**, с паттернами GoF из всех трёх групп и самописным DI-контейнером. Внешних зависимостей нет.

## Запуск и тестирование

```bash
go run .            # интерактивное меню
go run . --demo     # сквозной демо-сценарий и выход
go test ./...       # юнит-тесты
go test -cover ./...
```

Демо-сценарий (`--demo` или пункт 18 меню) проходит весь путь из ТЗ: заводит студентов и критерии → выставляет оценки → пытается нарушить инварианты (12 из 10, отрицательный балл, несуществующий критерий/студент, повторная оценка) → исправляет и отменяет оценку → считает итог по трём правилам → экспортирует итог в `pos_demo_report.csv` и `pos_demo_report.json`.

### Меню

| Группа     | Пункты                                                                                                            |
| ---------- | ----------------------------------------------------------------------------------------------------------------- |
| Студенты   | 1 — добавить, 2 — список, 3 — переименовать, 4 — удалить (вместе с оценками)                                      |
| Рубрикатор | 5 — добавить критерий (название, max_score, вес), 6 — показать, 7 — изменить вес, 8 — удалить (вместе с оценками) |
| Оценки     | 9 — выставить, 10 — все оценки, 11 — оценки студента, 12 — исправить, 13 — отменить                               |
| Итог       | 14 — итог студента, 15 — ведомость, 16 — сменить правило расчёта, 17 — экспорт (csv/json)                         |
| Прочее     | 18 — демо-сценарий, 0 — выход                                                                                     |

ID вводятся без учёта регистра (`s-1` = `S-1`), дробные баллы можно вводить и через точку, и через запятую.

## Логика решений

1. **Итог не хранится — он вычисляется.** Нет поля «итоговая оценка», которое можно забыть обновить. Итог каждый раз считает Domain Service `GradeCalculator` из текущего рубрикатора и текущих оценок. Поэтому он по построению согласован с набором оценок.
2. **Все инварианты живут в домене, а не в консоли.** Консоль ничего не проверяет: любые данные проходят через Value Objects, агрегат `Rubric` и фабрику `EvaluationFactory`. Обойти правила через UI невозможно.
3. **Маленькие агрегаты, связь по ID.** Студент, рубрикатор и оценка — отдельные агрегаты. Оценка ссылается на студента и критерий по идентификатору. Правило, затрагивающее два агрегата («оценка только по критерию из рубрикатора»), закрывает фабрика, которая получает рубрикатор на вход.
4. **Итог — по 10-балльной шкале НИУ ВШЭ.** Вес задаётся любым положительным числом и нормируется: доля критерия = `вес / сумма весов`. Это избавляет от лишнего инварианта «сумма весов = 1», который мешал бы добавлять критерии по одному.
5. **Изменение max_score критерия запрещено осознанно.** Это могло бы сделать уже выставленные оценки невалидными. Можно менять вес (на корректность оценок он не влияет) или удалить критерий вместе с оценками.

## Карта DDD

### Ubiquitous Language → код

| Термин предметной области               | В коде                                                                   |
| --------------------------------------- | ------------------------------------------------------------------------ |
| студент                                 | `domain.Student`                                                         |
| критерий (максимум, вклад в итог)       | `domain.Criterion` (`MaxScore`, `Weight`)                                |
| рубрикатор                              | `domain.Rubric`                                                          |
| оценка (балл, дата, комментарий)        | `domain.Evaluation` (`Score`, `gradedAt`, `comment`)                     |
| выставить / исправить / отменить оценку | `GradingService.Assess` / `Evaluation.Correct` / `GradingService.Cancel` |
| итог                                    | `domain.FinalGrade`, считается в `domain.GradeCalculator`                |
| правило итога                           | `domain.GradingPolicy`                                                   |
| ведомость                               | `application.GradeReport`                                                |

### Entity и Value Object

| Тип                                         | Что это                             | Почему                                                                                                                 |
| ------------------------------------------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `Student`                                   | **Entity**, корень агрегата         | Важна идентичность (`S-1`): студент остаётся тем же человеком после переименования                                     |
| `Rubric`                                    | **Entity**, корень агрегата         | Владеет критериями и охраняет их общие правила                                                                         |
| `Criterion`                                 | **Entity** внутри агрегата `Rubric` | Есть ID, на который ссылаются оценки. Вес можно поменять, но только через `Rubric` (методы изменения неэкспортируемые) |
| `Evaluation`                                | **Entity**, корень агрегата         | Оценку можно исправить, и это та же оценка `E-6` с новым баллом и датой                                                |
| `Score`, `MaxScore`, `Weight`, `FinalGrade` | **Value Object**                    | Нет идентичности, сравниваются по значению, неизменяемы, валидируют себя при создании                                  |
| `StudentID`, `CriterionID`, `EvaluationID`  | **Value Object**                    | Типизированные идентификаторы: нельзя случайно передать ID студента вместо ID критерия                                 |

**Пример разницы.** Два балла `Score(8)` взаимозаменяемы: это одно и то же значение, и «исправить балл» означает заменить VO целиком. А две оценки `Evaluation` с баллом 8 — разные факты: разные студенты, критерии, даты. Исправление оценки `E-6` меняет её состояние, но это всё ещё `E-6`.

### Инварианты и где они охраняются

| Правило                                                      | Где                                                                                                                |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| балл ≥ 0 и конечен                                           | `NewScore`                                                                                                         |
| max_score > 0, вес > 0                                       | `NewMaxScore`, `NewWeight`                                                                                         |
| **балл не выходит за пределы критерия**                      | `Criterion.Check`: вызывается в `EvaluationFactory.Create`, `Evaluation.Correct` и повторно в `GradeCalculator`    |
| **оценка только по критерию из рубрикатора**                 | `EvaluationFactory.Create` (через `Rubric.GetCriterion`)                                                           |
| исправить оценку можно только в рамках её критерия           | `Evaluation.Correct` (`ErrCriterionMismatch`)                                                                      |
| названия критериев уникальны (без учёта регистра), не пустые | `Rubric.AddCriterion`                                                                                              |
| ФИО студента не пустое                                       | `NewStudent`, `Student.Rename`                                                                                     |
| одна оценка на пару «студент × критерий»                     | `GradingService.Assess` + проверка в `GradeCalculator`                                                             |
| **итог согласован с текущим набором оценок**                 | `GradeCalculator.Calculate`: отклоняет чужие оценки, оценки по удалённым критериям, дубли и выход за шкалу [0, 10] |

### Repository (порты)

Интерфейсы `StudentRepository`, `RubricRepository`, `EvaluationRepository` объявлены в `internal/domain/repositories.go`. Домен говорит, что ему нужно хранить, но не знает, как. Реализации — in-memory адаптеры в `internal/adapters/memory`. ID выдаёт репозиторий (`NextID`) и резервирует его только при сохранении, поэтому неудачные попытки не оставляют пропусков в нумерации.

### Domain Service

`GradeCalculator` — правило, которое не принадлежит ни одной сущности: для итога нужны студент, весь рубрикатор и все оценки студента. Сервис проверяет согласованность входа и делегирует арифметику сменяемой стратегии (`GradingPolicy`).

## Архитектура: Ports and Adapters

**Стрелка зависимостей:** `adapters → application → domain`, а `di` знает всех. Домен не импортирует ничего, кроме стандартной библиотеки. Application импортирует только домен. Консоль импортирует только `application` (домен она не видит, работает с DTO `StudentView`, `GradeReport` и т.п.).

| Папка                       | Слой                     | Содержимое                                                                                                                                                                                                    |
| --------------------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `internal/domain`           | Domain                   | `Student`, `Rubric`, `Criterion`, `Evaluation`, VO, `EvaluationFactory`, `GradingPolicy` + реализации, `GradeCalculator`, порты репозиториев, доменные ошибки                                                 |
| `internal/application`      | Application / Use cases  | `StudentService`, `RubricService`, `GradingService` (выставить/исправить/отменить), `ReportService` (итог, ведомость, экспорт, смена правила), `PosFacade`, DTO-представления, порт `ReportExporter`, `Clock` |
| `internal/adapters/memory`  | Infrastructure (driven)  | in-memory реализации репозиториев                                                                                                                                                                             |
| `internal/adapters/export`  | Infrastructure (driven)  | `CSVExporter`, `JSONExporter`: маппинг `GradeReport` → файл                                                                                                                                                   |
| `internal/adapters/console` | Infrastructure (driving) | меню, ввод/вывод, демо-сценарий                                                                                                                                                                               |
| `internal/di`               | Composition root         | DI-контейнер                                                                                                                                                                                                  |

**Порты:**
- Driven: `domain.*Repository`, `application.ReportExporter`, `application.Clock`.
- Driving: `application.PosFacade`.

Чтобы добавить хранение в JSON-файл или БД, достаточно написать новый адаптер репозитория и поменять одну строку в контейнере. Домен и use cases не меняются.

## Паттерны GoF

| Группа        | Паттерн       | Где                                                                                                                              | Какую боль закрывает                                                                                                                                                                                                                                                                                                                                          |
| ------------- | ------------- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Порождающий   | **Factory**   | `domain/evaluation_factory.go` — `EvaluationFactory.Create`                                                                      | Единая точка создания оценки с инвариантами. Конструктор `Evaluation` недоступен вне домена (полей не задать снаружи), а фабрика сначала находит критерий в рубрикаторе, затем проверяет `score ∈ [0, max_score]`. Создать «12 из 10» или оценку по несуществующему критерию нельзя ни из консоли, ни из тестов, ни из будущего импорта                       |
| Структурный   | **Facade**    | `application/facade.go` — `PosFacade`                                                                                            | Консоли не нужно знать о четырёх сервисах, репозиториях, калькуляторе и экспортёрах. Она вызывает один объект, и сценарии не размазываются по UI. Замена консоли на HTTP или Telegram-бота затронет только адаптер                                                                                                                                            |
| Структурный   | **Decorator** | `domain/grading_policy.go` — `RoundedPolicy`                                                                                     | Округление — отдельная от формулы итога забота. Декоратор оборачивает любую стратегию и округляет её результат (до целого — как в ведомости, до сотых — для просмотра). Без него пришлось бы дублировать каждую стратегию в «округлённом» варианте. Декораторы комбинируются (`RoundedPolicy(RoundedPolicy(...))`, см. тест `TestRoundedPolicy_CanBeStacked`) |
| Поведенческий | **Strategy**  | `domain/grading_policy.go` — `GradingPolicy`, `WeightedAveragePolicy`, `CurrentProgressPolicy`; используется в `GradeCalculator` | Правило итога сменяемо без правки Domain Service. «Итоговая оценка» считает неоценённые критерии нулём, «текущая успеваемость» учитывает только оценённые. Правило переключается в рантайме (пункт 16 меню). Новое правило (например, с блокирующим экзаменом) — это новый тип, а не новый `if` в калькуляторе                                                |

Template Method и Builder сознательно не использованы. Импорта ведомостей в ТЗ нет, а рубрикатор собирается по одному критерию через агрегат, поэтому эти паттерны были бы «для галочки».
